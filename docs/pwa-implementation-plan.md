# English OK：iPhone PWA 试用实施方案

日期：2026-10-28。状态：已进入实施；本地代码、自动验证和人工验收状态以 pwa-verification.md 为准。尚未发布网站。

## 1. 本期目标和范围

第一版达到：Safari 打开 HTTPS 网站，添加到主屏幕；首次完整缓存后可在断网、电脑关机时重新打开并背词；每次反馈保存到本机，退出重开后继续；支持 JSON 备份导入与导出。

沿用现有界面、词库、学习规则和数据格式。登录、跨设备自动同步、发音、推送、正式每日任务及原生 iOS 打包另行实施。本期不以新增这些功能作为完成条件。

截至本次检查，web 运行文件共 12 个，合计 2,125,638 字节，约 2.1 MB（十进制），含 1165 个主词、1607 个可学习词义。加入图标和缓存逻辑后体积会有所增长。下载完成以实际检查结果为准，不承诺固定秒数。

## 2. 基础部署选择

试用默认采用 GitHub Pages + 平台提供的 github.io 地址 + HTTPS，不购买域名，不租用服务器。发布资源仅来自经过检查的网站构建目录。

正式发布前读取 GitHub 仓库当前可见性、账号和 Pages 可用性，不自动修改仓库可见性。GitHub Free 的 Pages 适用于公共仓库；其他套餐对私有仓库的支持见官方文档。如果现有仓库保持私有且当前套餐不支持，可使用一个仅存网站发布文件的独立公共仓库，具体仓库在发布前确定。

普通 Pages 发布的网站及其中的词库可被获得地址的其他人访问。本方案没有访问密码或用户鉴权。如果要求仅自己可访问，需要在上线前调整托管方式和访问控制。个人学习记录仍保存在手机 IndexedDB；应用不增加学习记录上传逻辑。

托管负责首次下载和更新。离线缓存完整且未被清除时，日常背词无需联网；缓存被系统或用户清除后，需要联网重新下载。首次下载和更新需在用户实际网络中验证可达性。

## 3. 阶段一：保护旧记录并确认基线

执行工作：

1. 在当前真正保存学习进度的设备和网址中导出 JSON 备份，保存在网站数据之外。
2. 记录原网址、当前学习位置和累计记录数量；测试使用独立浏览器环境，避免覆盖真实记录。
3. 执行现有 npm test，记录基线结果；检查已有移动端布局和备份流程。
4. 确认发布输入仅包含程序、内置词库和空白初始化结构，不包含个人 JSON、个人 SQLite、原始 PDF、临时文件或开发目录。

验收：已有备份文件可读取；基线失败如果存在，已记录原因和影响；后续操作不依赖清空网站数据。

注意：电脑与手机、局域网地址与 HTTPS 地址的数据不能假定共享。先导出，再在主屏幕应用中导入；导入会替换目标环境的学习记录。

## 4. 阶段二：增加 PWA 入口和安装说明

计划新增 web/manifest.webmanifest、web/icons/ 下的图标、web/pwa.mjs；修改 web/index.html、web/style.css 和静态服务的 MIME 配置。

具体实现：

- 应用名称 English OK，配置 start_url、scope、稳定的应用 id 和 standalone 显示方式。
- 提供 192、512 像素应用图标及 180 像素 Apple touch icon；第一版采用与现有配色一致的简单图标。
- 路径兼容网站根目录和 /english-ok/ 一类项目子目录，避免发布后脚本、词库或 Service Worker 指向错误位置。
- 设置页面提供 Safari 分享菜单安装说明；普通局域网 HTTP 显示需要 HTTPS 才能准备离线资源。
- 继续使用现有 safe-area 和动态视口适配，补充小屏、横屏及长内容检查。

验收：清单和图标可以正确读取，桌面模拟布局无明显遮挡；真实安装表现留到 iPhone 阶段确认。

## 5. 阶段三：实现完整离线启动

计划新增 web/sw.js、发布准备脚本及资源版本清单。

缓存范围：入口 HTML、CSS、应用模块、存储和业务模块、SQLite JS/WASM、内置 vocabulary.sqlite、learning.sql、应用清单和图标。运行时按实际依赖核对清单。

关键规则：

1. 发布脚本根据程序和词库内容生成版本标识及资源校验信息；词库变动也必须触发新版本。
2. 新版本资源全部下载并校验成功后才可进入可用状态。安装失败不提示离线就绪，也不删除仍可用的旧版本。
3. 同一版本资源从该版本缓存读取，避免网络更新导致页面、脚本和词库混用；安装时的资源校验用于拒绝部署过程中不一致的资源组合。
4. 仅处理当前应用路径和必要请求，不把任意其他页面请求返回为应用首页。
5. 用户界面分别显示“正在准备离线资源”“离线资源已准备好”“准备失败，可重试”。就绪状态同时确认资源完整及当前页面已受对应 Service Worker 控制。
6. 缓存只用于发布资源。个人进度继续使用现有 IndexedDB，不写入发布资源缓存。

验收：先在线完成准备，再关闭本地服务并从原地址重新打开；界面、词库及学习反馈均可用。弱网或缺少 WASM、词库等关键资源时不能误报就绪。

开发入口 localhost 可用于电脑测试。iPhone 访问普通局域网 HTTP 不能替代 HTTPS 的离线测试。

## 6. 阶段四：更新和数据管理

第一版采用保守的更新流程：后台发现并准备新版本，提示有更新；当前学习页面继续使用旧版本，不在学习过程中自动刷新或强制激活。用户结束学习，关闭旧版本相关窗口后，再打开并验证新版本。提示中解释可能需要关闭 Safari 中的旧页面及主屏幕应用窗口。

更新程序和词库时保留 IndexedDB。仅清理本应用过期资源缓存，不能清除个人数据库或其他应用缓存。显示应用版本和词库版本，便于判断是否更新成功。

保持现有 JSON 备份格式和替换式恢复语义；iPhone 上优先实现并验证系统文件分享/保存，按能力保留下载回退方案。恢复仍需用户确认，失败保留原记录。

验收：更新前后的进度数量、学习位置和记录一致；旧队列延续现有规则；坏备份拒绝导入；iPhone 导出的 JSON 可以重新导入。JSON 为本期必验备份格式，额外 SQLite 导出沿用并记录兼容情况。

回退规则：保留上一个已验证发布包；发布失败时可以重新部署。已安装客户端仍需遵循更新生命周期，重新部署不等于立即替换全部客户端。回退包不能低于已有学习数据结构的兼容要求；回退前先备份学习记录。

## 7. 阶段五：构建、检查与 HTTPS 发布

准备独立发布目录，采用文件白名单组装，而非递归上传整个项目。发布包包括网站资源及所需的第三方许可声明。

计划增加 prepare:pwa 命令以生成发布目录、缓存版本及校验清单。该命令属于本次待实现内容，当前尚不存在。首次改造后的本地检查顺序预计为：

```powershell
npm test
npm run prepare:pwa
```

prepare:pwa 应可重复执行，并检查缺失资源和路径。既有 npm run prepare:web 可在依赖更新后用于复制 sql.js 运行资源，发布脚本需明确是否调用它。

配置 .github/workflows 下的 Pages 发布流程：先运行检查和准备脚本，再上传指定发布目录。第一版通过 workflow_dispatch 手动触发，避免每次整理词库或修改文档都自动上线。用户在 GitHub 仓库 Settings → Pages 中将发布来源设为 GitHub Actions，随后运行发布任务。实际分支和仓库路径按当前远端配置确定。

完成本地改造、检查和发布文件清单后，提供可审阅差异，再执行首次公网发布。当前讨论方案本身不执行发布。

验收：GitHub Pages 给出的实际 HTTPS 地址可在用户 iPhone 网络中打开；子目录资源均为成功响应；离线就绪提示出现。若网络不可达，先解决托管可达性，不以桌面结果代替手机结果。

## 8. 阶段六：iPhone 真机验收

测试前记录 iPhone 型号与 iOS 版本。使用 Safari 普通浏览模式打开实际 HTTPS 地址，完成缓存，再从分享菜单添加到主屏幕。如果系统显示“作为 Web App 打开”，启用该选项。重新从图标进入后再次确认离线就绪，随后在这个环境导入需要迁移的备份。

| 检查 | 操作 | 通过标准 |
| --- | --- | --- |
| 安装 | 添加到主屏幕并从图标启动 | 名称、图标正确，独立界面正常 |
| 冷启动离线 | 飞行模式且 Wi-Fi 关闭，结束应用后重新打开 | 学习页和词库正常加载 |
| 离线学习 | 断网完成几个学习反馈 | 保存成功，没有伪成功提示 |
| 进度恢复 | 退出、重开；补做手机重启后检查 | 记录数量和学习位置符合操作结果 |
| 手机布局 | 长例句、小屏、横竖屏、滚动详情 | 操作按钮可达，内容可完整查看 |
| JSON 备份 | 导出至“文件”，再选择备份恢复 | 文件可读，恢复结果一致 |
| 异常备份 | 导入损坏或不支持的 JSON | 明确报错，原记录保留 |
| 更新 | 联网准备新版本，结束学习后重开 | 版本变化，原进度保留，离线仍可用 |
| 首次缓存失败 | 测试环境中中断资源下载 | 不提示离线就绪，联网后可以重试 |

任何一项未通过，都记录设备、版本、操作和结果，修复后重验相关项目。桌面自动测试通过不等于 iPhone 真机通过。
